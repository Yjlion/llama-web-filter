Management HTTPS

Serve this interface over TLS instead of plain HTTP — including the login request. Restart after saving changes.

Before you enable this without a certificate below: the built-in CA signs the certificate, so browsers warn until that CA is installed — and the CA download at /api/ca-cert would itself be behind that warning. Install certs/ca.crt on your machine first, or supply a publicly trusted certificate. WPAD clients will also stop fetching /proxy.pac from an endpoint they do not trust, so leave this off if you distribute PAC from this port.

Set both or neither. The pair is loaded and checked when you save, so a bad path is reported here rather than taking the interface down on the next restart.

Authentication

Require a password to open this management interface.

Stored salted + hashed (PBKDF2). Put the UI behind HTTPS/VPN if exposed beyond a trusted network.

Proxy Authentication

Require clients to present a username and password before they can use the proxy (HTTP Basic, RFC 7235). Applies to HTTP proxy requests and HTTPS CONNECT tunnels.

Password is stored salted + hashed (PBKDF2). Credentials travel over the network as Base64 (HTTP Basic) — use on a trusted LAN or behind HTTPS/VPN.

Monitoring

Prometheus metrics and a health endpoint for load balancers. /health is always available and needs no authentication — a load balancer cannot log in.

Only needed when management authentication is on: a Prometheus scraper cannot log in, so it sends this instead as Authorization: Bearer <token>. It grants read access to the counters and nothing else — it is not a second management password, and it is stored and shown in plain text because it has to be copied into a scrape config.

Counters are per-process: if you run webfilter proxy and webfilter mgmt as separate processes, scrape the one serving traffic — the management process reports zeroes.
